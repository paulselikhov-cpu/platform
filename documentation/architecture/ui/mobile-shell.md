# Мобильный shell: раскладки, навигация и переносимость в нативное приложение

> «Как реализовано». Факты о текущем коде (frontend `platform-ui`).

## Задача

Сделать чат пригодным для телефона (современный вид пузырей, полноэкранные
экраны, нижняя навигация) так, чтобы логика затем переносилась в нативное
приложение (Android/iOS) без переписывания.

## Разделение: логика отдельно от раскладок

```
ChatLayout            /chat          guard «есть персонаж», всегда <router-outlet>
└── ChatShell          любой /chat/*   решает раскладку по ширине окна
    ├── ChatShellState               логика сессии (сигналы, роутинг, фича локации)
    ├── ChatDesktop   > 900px        колонка NavRail · сайдбар · контент · CharacterPanel
    └── ChatMobile    ≤ 900px        шапка · полноэкранный контент · таб-бар
```

`ChatShellState` (`layout/chat-shell/chat-shell-state.ts`) объявлен в
`providers` шелла: `ActivatedRoute` дочернего маршрута доступен только там,
а состояние должно сбрасываться при уходе из локации.

Граница раскладок — ширина окна ≤ 900px, а не тип устройства: планшет в
портретной ориентации на узком экране получает мобильный интерфейс.

## Навигация: всё состояние в URL

Вкладка активна, только если она в маршруте (`data.tab`), поэтому любой
экран открывается прямой ссылкой и переживает F5.

| Маршрут | Экран | Вкладка |
|---|---|---|
| `/chat` | список локаций | Локации |
| `/chat/location/:code/main` | главное меню локации | Локации |
| `/chat/location/:code/feature/:id` | раздел фичи | Локации |
| `/chat/location/:code/room/:roomId` | комната (полный экран) | Локации |
| `/chat/location/create`, `/chat/location/find`, `/chat/work` | формы | по контексту |
| `/chat/district` | район | Район |
| `/chat/me` | персонаж | Персонаж |
| `/chat/settings` | настройки (полный экран) | Персонаж |

Это ровно та схема, которая в нативном приложении станет deep-link'ами.

## Один список пунктов навигации

`shared/nav/nav-items.factory.ts` — единственное место, где перечислены пункты
приложения, условия их видимости (`isStaff`, наличие лицензии), бейджи и
команды. Пункт сгруппирован по `NavGroup` (`locations` / `district` / `profile`) —
это те же три мобильные вкладки, поэтому группировка одна для обеих раскладок.

- `NavRail` (десктоп) рисует все группы вертикальной колонкой.
- `MobileTabBar` (мобила) показывает свою группу, а её пункты — внутри
  экрана вкладки.
- Пункт может нести несколько команд: десктоп выполняет `open-modal`
  (районные разделы и настройки открываются окном), мобила — `navigate`.
  `pickCommand()` выбирает первую поддерживаемую.

Действия фичи локации в этот список **не** входят: их источник — сама фича
(`LocationFeature.menuItems`), они привязаны к открытой локации, а не к
аккаунту.

## Что означает `⋮`

`⋮` (ActionsMenu) — **действия того, что открыто**:

| Экран | Источник пунктов |
|---|---|
| главное меню локации, раздел фичи | `LocationFeature.menuItems` |
| комната | `resolveRoomActions(location, room)` (пока пусто) |
| список локаций, вкладки «Район» / «Персонаж» | — кнопки нет |

Настройки приложения открываются отдельной кнопкой `⚙️`, поэтому `⋮` никогда
не означает «настройки» и не путается с ними. Кнопка плоская и одинаковая
на обеих платформах; размер адаптируется в `actions-menu.scss`.

Кнопка `⚙️` есть **только на вкладке «Персонаж»** — на остальных экранах
мобильной шапки её нет, а на десктопе те же настройки открывает пункт `NavRail`.

## Экран локации: меню и комнаты на одном экране

Отдельного маршрута для списка комнат нет: `/chat/location/:code/main`
показывает и разделы фичи, и комнаты локации. Переход в комнату уводит на
`/chat/location/:code/room/:roomId`, поэтому от локации до чата — один тап.

- `LocationMain` на мобиле занимает размер своего контента (`flex: none`),
  иначе он забирал свободную высоту и прижимал список комнат к низу.
- Между меню разделов и списком комнат — разделитель `.mobile__divider`:
  без него два разных списка сливались в один столбик.
- Пункт «Главная» в списке комнат скрыт (`[showHome]="false"`): он вёл бы на
  уже открытый экран. На десктопе пункт остаётся — там главное меню
  находится в соседней панели, и переход между ними осмыслен.
- Шапка экрана одна — `mobile__header`: `LocationHeader` на мобиле скрыта,
  иначе над списком локаций рисовались две шапки подряд.

## Шапка и вкладки

`mobile__header` обслуживает все экраны: `←`, иконку, заголовок и меню.
Заголовок вычисляется в `headerTitle` — название комнаты, локации, «Район»,
«Персонаж» или формы. Внутри локации иконка шапки — **иконка самой локации**
(мэрия, банк, тюрьма), а на списке локаций и вкладках — иконка вкладки.
Карта берётся из общего `features/location/location-icons.ts`, чтобы шапка и
главное меню не разошлись.

Вкладка «Локации» **не подсвечивается** внутри локации: `MobileTabBar`
принимает `active: MobileTab | null`, и раскладка передаёт `null`, пока
`panel === 'location'`. Вкладка — это раздел приложения, а локация — его
содержимое, поэтому подсветка означала бы смену раздела, которой не было.
Бейдж непрочитанных на вкладке «Район» дублирует число из `NavRail`.

## Вид ленты

- **Пузыри**: свои справа, чужие слева, ширина ограничена токеном
  `--bubble-max-width`. Оформление общее для дескстопа и мобили.
- **Группировка** (`features/chat/chat-area/utils/message-grouping.util.ts`):
  сообщения одного автора подряд сливаются — аватар и ник только у первого.
  Группа рвётся при смене автора, разрыве в полчаса, смене дня или удалении.
- **Разделители дней** (`DayDivider`): «Сегодня» / «Вчера» / дата, одинаково
  на обеих платформах.
- Лента рендерится одним циклом по `TimelineRow` (разделитель или сообщение),
  поэтому разделитель не может «потеряться» между сообщениями.

## Touch

- **Свайп-назад** от левого края (`SwipeBackDirective`): жест начинается в
  полосе 24px, срабатывает при смещении вправо 40px. Работает на `document`
  в фазе capture, потому что палец может уйти на ленту сообщений.
- **Long-press** на сообщении открывает контекстное меню: события `contextmenu`
  мыши на тач-экранах не бывает.
- **Safe-area**: `--mobile-safe-top/bottom` из `env(safe-area-inset-*)`;
  шапка и таб-бар не заезжают под вырез камеры и системную панель жестов.

## Переносимость в нативное приложение

| Что | Куда переносится |
|---|---|
| `ChatShellState`, `buildNavItems()`, `LocationFeature` | логика без изменений |
| REST-контракты и WS-топики | без изменений |
| URL-маршруты | deep-link'и |
| `NavItem` / `RoomMenuItem` | плоские данные без DOM → `PopupMenuButton` / `BottomSheet` |
| шаблоны, директивы скролла и жестов | платформенный слой |

## Что осталось фейковым

Лента новостей района (`shared/components/district-news-feed/`) задана локально:
бэкенд не отдаёт ленту событий района. Компонент общий для правой панели
десктопа и вкладки «Район», поэтому замена на реальные данные затронет оба
экрана сразу.

Компонент лежит в `shared/components/`, а не в `layout/mobile/`: его показывают
обе раскладки, и размещение в мобильной ветке заставляло `shared` импортировать
вверх по дереву (`NG1010: Unknown reference`).

`CharacterPanel.maxEnergy` — константа 100, бэкенд не отдаёт максимум.
