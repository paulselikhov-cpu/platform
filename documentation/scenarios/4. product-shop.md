# Продуктовый магазин (сценарий №4)

## 1. Что за функционал (из черновика пользователя)

Системная локация "Магазин 24/7" (`location.code = GENERAL_MARKET`). Пользователь заходит в локацию в комнату — торговый зал (`room.code = SHOP_MAIN`).

В торговом зале одновременно: чат с другими посетителями (видно, кто онлайн — уже работает при входе в комнату) и корзина покупок пользователя (привязана к персонажу, не шарится, состояние в `localStorage`). Имитация реального похода в магазин: покупаешь продукты и при этом общаешься с людьми в зале.

## 2. Архитектурные решения (договорились)

### 2.1. Фича комнаты (Room Feature) — универсальный механизм

Не только для магазина, а базовый функционал на будущее: у разных комнат разных локаций могут быть свои вкладки-фичи (как у локаций уже есть свои фичи через `LocationFeature`).

- Фича комнаты активируется только для конкретной пары `location.code + room.code`.
- Новая фича комнаты = новый класс + одна строка в фабрике `resolveRoomFeature`. Ядро (`RoomView`, `chat-area`) не меняется при добавлении каждой новой фичи.
- По умолчанию в комнате только вкладка «Чат». Если у комнаты есть фича — появляются дополнительные вкладки.
- фичи - таб-бар внизу экрана над app-message-input
- При переключении вкладок `chat-area` остаётся смонтированным (скролл сохраняется, WS-подключение не рвётся, нет переподключения).
- Навигация только локальная внутри `RoomView` (без изменений URL, без `?tab=` на старте).

### 2.2. Корзина
- Привязка к `characterId`. Состояние хранится в `localStorage` (ключ `babich_market_cart_{characterId}`).
- Кнопка «Очистить корзину» — просто чистит `localStorage`.
- Кнопка «Оплатить» — проверка баланса (мок на старте, бэкенд позже), shared модалка `app-confirm-modal` («вы уверены, что хотите оплатить покупку?»), при подтверждении — транзакция на бэкенде, очистка корзины.
- Корзина существует только внутри комнаты торгового зала. При выходе из комнаты доступ теряется, но данные в `localStorage` остаются.

### 2.3. Товары и таб «Продукты» (на старте — мок)

На бэкенде пока нет сущностей `location_items` / товара склада. На старте используются моковые товарные карточки на фронте.

**Таб «Продукты»** — вторая вкладка в таб-баре торгового зала (рядом с «Корзиной»). Показывает сетку карточек товаров:

- Карточка товара: иконка еды, название, сколько энергии пополняет, цена, количество на складке.
- Инкрементные кнопки `− / +` для выбора количества (не больше остатка на складе).
- Кнопка «Положить в корзину» — добавляет выбранное количество в корзину пользователя (в `localStorage`).
- Если товара нет на складе — карточка disabled, кнопка «Положить в корзину» недоступна.

**Фильтрация по типу товара:**
- `locationItem.type = food` — товары питания.
- `food` — это справочник на бэкенде с полем `type`: мясо, овощи, напитки и т.д.
- На фронте — селект/фильтр «Все | Мясо | Овощи | Напитки», по умолчанию «Все».

Бэкенд-доработка фиксируется как будущая работа (см. §5).


## 3. Что требуется на бэкенде (будущая доработка, фиксируем здесь)

| Сущность / изменение | Назначение |
|---|---|
| `Room.code` | Добавить код `SHOP_MAIN` для комнаты торгового зала. Фронт должен получать `room.code` при загрузке комнаты. |
| `LocationItem` (склад локации) | Товары на складе локации: товар + остаток + `type` (например, `food`). |
| `ItemType` enum | Типы товаров (food, …). Не называть enum и entity одинаково (правило нейминга). |
| `UserItem` | Инвентарь персонажа: купленные товары. |
| `Wallet` | Счёт локации (магазина) — новая сущность, куда зачисляются средства при оплате как для локаций, так и для пользователей. |
| `ItemPurchasedEvent` (или аналогичное) | Доменное событие покупки, вписывается в event-архитектуру проекта. |
| REST-эндпоинты | Список товаров торгового зала, оплата/транзакция, проверка баланса (достаточно ли монет). |
| Проверка прав | Кто может пополнять склад (сотрудник / директор системной локации), кто может покупать (любой житель района). |





## 4. План реализации

### Этап 1. Каркас Room Feature (фронтенд)

Новые файлы в `platform-ui/projects/babich-chat-ui/src/app/features/room-feature/`:

1. `room-feature.interface.ts` — `RoomFeature`, `RoomFeatureTab`, `RoomFeatureContext`.
2. `base-room-feature.ts` — `BaseRoomFeature` (абстрактный базовый класс, по аналогии с `BaseLocationFeature`).
3. `room-feature.factory.ts` — `resolveRoomFeature(ctx)`: switch по `room.code`, пока только `SHOP_MAIN` → `ShopMainRoomFeature`.
4. `room-feature.store.ts` — `RoomFeatureStore` (сигнал активной фичи, `acquire`/`release`; не сбрасывается при переключении вкладок, сбрасывается при смене комнаты).

### Этап 2. Фичи комнаты для торгового зала

Новые файлы в `features/room-feature/`:

5. `shop-cart-room-feature.ts` — `ShopMainRoomFeature extends BaseRoomFeature`, две вкладки: `products` («Продукты») и `cart` («Корзина»).
6. `shop-cart.service.ts` — `ShopCartService`: чтение/запись корзины в `localStorage` по ключу `characterId`, методы `add`, `remove`, `clear`, `total`, `items`.
7. `shop-cart-panel.component.ts/html/scss` — панель корзины: список товаров, счётчик qty, общая сумма, кнопка «Очистить корзину», кнопка «Оплатить» (disabled при пустой корзине).
8. `shop-products.service.ts` — сервис моковых товаров: список `MockGood`, фильтрация по `type` (food), по `foodType` (мясо/овощи/напитки).
9. `shop-products-panel.component.ts/html/scss` — панель товаров: фильтр по `foodType`, сетка `shop-product-card`.
10. `shop-product-card.component.ts/html/scss` — карточка товара: иконка, энергия, цена, остаток на складе, инкрементные кнопки qty, кнопка «В корзину».
11. `mock-goods.ts` — моковый каталог товаров с полями `type`, `foodType`, `energy`, `stock`, `price` + константы `FOOD_TYPES` / `FOOD_TYPE_LABELS`.

### Этап 3. Интеграция в `RoomView`

Изменения в `features/location/room-view/`:

9. `room-view.ts` — инъекция `RoomFeatureStore`, вызов `acquire({ room, location, injector })` при входе в комнату, сигналы `tabs()` (всегда «Чат» + вкладки из фичи комнаты) и `activeTab()`.
10. `room-view.html` — нижний таб-бар (виден только если есть фича комнаты): кнопка «Чат» + кнопки вкладок фичи; активная вкладка через `ngComponentOutlet` с input `{ roomId, locationId, characterId }`; `chat-area` остаётся в DOM при переключении.
11. `room-view.scss` — стили таб-бара (position bottom, фиксированная высота).

### Этап 4. Проверка

12. Запуск фронтенда, вход в комнату торгового зала (`location.code = GENERAL_MARKET`, `room.code = SHOP_MAIN`):
    - таб-бар появляется только в этой комнате: «Чат», «Продукты», «Корзина»;
    - переключение «Чат ↔ Продукты ↔ Корзина» не сбрасывает скролл чата и не переподключает WS;
    - в табе «Продукты»: сетка карточек, фильтр по `foodType`, инкремент qty, кнопка «Положить в корзину»;
    - добавление товара в корзину сохраняется в `localStorage`;
    - «Очистить корзину» и «Оплатить» (мок) работают.

### Этап 5. Документация

13. `scenarios/index.md` — статус scénario №4.
14. `project-card.md` — таблица сценариев.

## 5. Что НЕ входит в этот спринт

- Бэкенд-сущности `LocationItem`, `UserItem`, `ItemType`, `Wallet` — только документируются (§3).
- Реальное списание монет и зачисление на `Wallet` магазина — мок на фронте.
- URL-навигация на вкладку фичи комнаты (`?tab=products` / `?tab=cart`) — только локальное переключение.
- Общая корзина между комнатой и главным меню локации — корзина только внутри комнаты торгового зала.

## 6. Вопросы (решены)

| Вопрос | Решение |
|---|---|
| Куда привязана корзина | К `characterId`, `localStorage` |
| Где таб-бар | Внизу экрана, только если есть фича комнаты |
| Что с chat-area при переключении | Остаётся смонтированным, скролл и WS не сбрасываются |
| Кто получатель средств при оплате | `Wallet` локации (магазина) — будущая сущность бэкенда |
| Как называть счёт локации | `Wallet` |
| Нужна ли фича комнаты универсальная | Да, на будущее для других комнат и локаций |
| food — справочник на бэкенде | Да, поле `type` (мясо, овощи, напитки…); на старте мок на фронте |
