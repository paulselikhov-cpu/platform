# Сценарий №1. Первый вход в дефолтный район

## Цель
Новый пользователь регистрируется, попадает в игру, выбирает район, видит системные локации и может начать взаимодействие с игровым миром.

---

## Шаг 1. Регистрация

**Пользователь:** заполняет форму регистрации (логин, email, пароль).

**Система:**
- POST `/api/auth/register` — создаёт пользователя и JWT-токен
- Редиректит на `/main-menu`

> ✅ **Реализовано.** `RegisterComponent` → `AuthService.register()` → `router.navigate(['/main-menu'])`.

---

## Шаг 2. Главное меню (приветственная заставка)

**Пользователь:** после регистрации или логина видит приветственный экран.

**Система:** показывает карточку с:
- Названием платформы «BabichChat»
- Кратким описанием
- Кнопкой **«🎮 Войти»** — переход к выбору района (`/district-select`)
- Кнопкой **«🚪 Выйти»** — логаут и возврат на экран логина

В будущем на этом экране могут отображаться новости платформы, события и т.д.

> ✅ **Реализовано.** Компонент `MainMenu` (роут `/main-menu`).
> - После регистрации → `/main-menu`
> - После логина → `/main-menu`
> - «Войти» → `/district-select`
> - «Выйти» → `AuthService.logout()`

---

## Шаг 3. Выбор района + проверка персонажа

**Пользователь:** нажимает «Войти» в главном меню → видит список доступных районов.

**Система:**
- `GET /api/districts` — загружает список районов
- На старте доступен один район: **Центральный** (code: `CENTRAL`)
- Каждый район показывается карточкой: название, описание, теги системных локаций

**Логика выбора района (клик по карточке):**

1. Район выделяется визуально (класс `--selected`)
2. `districtId` сохраняется в `localStorage` через `CurrentChatUserService.setDistrictId()`
3. Для выбранного района немедленно загружается персонаж:
   `GET /api/chat/users/{userId}/characters?districtId={districtId}`
4. Результат проверки отображается **внутри той же карточки района** (под тегами локаций):

   **Вариант А: Персонаж не создан** — внутри карточки появляется блок:
   > «У вас ещё нет персонажа в этом районе» + кнопка **«➕ Создать персонажа»**

   **Вариант Б: Персонаж уже создан** — внутри карточки появляется профиль персонажа:
   > Аватар + имя + рейтинг ⭐ + монеты 🪙 + статус + кнопка **«🎮 Войти в район»**

> ✅ **Реализовано.** Компонент `DistrictSelect` (роут `/district-select`).
> - API: `GET /api/districts`
> - При клике на карточку: `selectDistrict(district)` → `setDistrictId()` + `loadCharacterForDistrict()`
> - Профиль персонажа отображается **внутри выбранной карточки района**, а не отдельно — связь «персонаж ↔ район» наглядная
> - Если персонаж есть: `character-profile` с кнопкой «🎮 Войти в район» → `/chat`
> - Если персонажа нет: сообщение + кнопка «➕ Создать персонажа» → `/character-create`

---

## Шаг 4. Вход в чат (после выбора/создания персонажа)

**Пользователь:** нажимает «🎮 Войти в район» (или создаёт персонажа → возвращается на `/district-select` → нажимает «Войти»).

**Система:** загружает:
1. **Приватные локации пользователя** — `GET /api/locations/my?userId=N` (если есть)
2. **Районы с системными локациями** — `GET /api/districts`

**Что видит пользователь:**
- В сайдбаре — секция **«Мои локации»** (пустая, если нет ни одной) и секция **«Системные локации»** с районом «Центральный» и его 8 локациями с соответствующими иконками:
  - 🏛️ Мэрия
  - 📢 Площадь Ленина
  - 👮 Полицейский участок
  - 🔒 Тюрьма
  - 🏦 Банк
  - 📦 Склад
  - 🛒 Рынок
  - 🏘️ Рынок недвижимости
- По умолчанию никакая локация не выбрана, основная панель пуста (`LocationEmpty`)
- Во всех локациях пользователь оффлайн

> ✅ **Реализовано.** Sidebar загружает районы (`DistrictService.getAllDistricts()`),
> отображает системные локации с иконками, приватные локации загружаются.

**Проверка персонажа** происходит на этапе выбора района (Шаг 3), а не на отдельном шаге.

---

**Важные замечания:**

**Архитектура персонажей:**
- Персонаж (ChatUser) привязан к конкретному району через поле `districtId`
- Один пользователь может иметь множество персонажей, но не более одного в одном районе
- Персонаж развивается в рамках района, к которому привязан

**Удаление персонажа:**
- В текущей логике удаление персонажа из района невозможно, так как на нём завязаны механики (например, роль губернатора)
- При удалении персонажа система должна очистить все его данные из района
- Реализовать в **[Сценарий №1.2. Удаление персонажа из района](delete-person-from-district.md)**

## Шаг 5. Навигация по системным локациям

**Пользователь:** кликает на системную локацию в сайдбаре (например, «Площадь Ленина»).

**Система:**
- Локация подсвечивается (активный стиль с левой рамкой)
- Открывается `LocationView` с заголовком локации и бейджем **«Системная»**
- Загружаются комнаты системной локации — `GET /api/locations/{id}/rooms`
- Отображается список комнат (для Площади Ленина: «Площадь», «Тёплые трубы»)
- Пользователь выбирает комнату → открывается чат (`ChatArea`)

> ✅ **Реализовано.**
> - `.public-location-item` кликабелен с эмитом `systemLocationSelected`
> - `LocationView` адаптирован: поля `template`, `inviteCode`, `isPublic` — опциональны
> - API `GET /api/locations/{id}/rooms` работает для системных локаций
> - Бейдж «Системная» отображается акцентным цветом

## Технические заметки

### Схема навигации (роутинг)
```
/login → /main-menu → /district-select (клик по району → персонаж внутри карточки) → /character-create (если нет) → /district-select (с профилем) → /chat
/register ↗
```

### Ключевые изменения в DistrictSelect (последняя версия)

**Проблема (было):** Профиль персонажа отображался отдельно от списка районов, не было визуальной связи «персонаж ↔ район».

**Решение (стало):** Профиль персонажа встроен внутрь карточки района:
1. Пользователь кликает на карточку района
2. Район выделяется, districtId сохраняется в localStorage
3. Загружается персонаж для этого района через API
4. Внутри выбранной карточки (под тегами локаций) появляется:
   - Либо профиль персонажа с кнопкой «🎮 Войти в район»
   - Либо сообщение «У вас ещё нет персонажа» с кнопкой «➕ Создать персонажа»

**Компоненты:**
- `DistrictSelect.ts` — сигналы: `districts`, `selectedDistrict`, `characterForSelected`, `checkingCharacter`
- `DistrictSelect.html` — карточки районов с условным блоком `@if (isSelected)` внутри
- `DistrictSelect.scss` — стили для `.district-card--selected`, `.district-card-character`, `.character-profile`

### API
- `GET /api/auth/register` — регистрация
- `GET /api/auth/login` — логин
- `GET /api/districts` — список районов с системными локациями
- `GET /api/districts/{id}` — район по ID
- `GET /api/districts/{id}/system-locations` — системные локации района
- `GET /api/locations/{id}/rooms` — комнаты локации (работает и для системных)
- `GET /api/chat/users/{userId}/characters?districtId={districtId}` — проверка персонажа в районе
- `POST /api/chat/users/{userId}/characters` — создание персонажа в районе

### Frontend
- `ILocation` — универсальный интерфейс (поля `template`, `inviteCode`, `isPublic` — опциональны, добавлено `type?: string`, `memberRole?: 'SYSTEM'`)
- `Sidebar` — эмитит `systemLocationSelected` для системных локаций, словарь иконок по `PublicLocationType`
- `MainMenu` — приветственная заставка (роут `/main-menu`)
- `DistrictSelect` — выбор района (роут `/district-select`)
  - Загружает список районов через `GET /api/districts`
  - При клике на карточку района: устанавливает район, сохраняет в `localStorage`, загружает персонажа
  - **Профиль персонажа отображается внутри карточки района** — наглядная связь
  - Если персонаж есть — профиль (аватар, имя, рейтинг, монеты, статус) + кнопка «🎮 Войти в район» → `/chat`
  - Если персонажа нет — блок с текстом и кнопкой «➕ Создать персонажа» → `/character-create`
  - Если район уже был выбран ранее (из `localStorage`), он подсвечивается при загрузке
- `CharacterCreateComponent` — форма создания персонажа (роут `/character-create`, реализовано)
  - Поля: characterName, gender, weight, height, badHabits
  - После создания — редирект на `/district-select` (не на `/chat`)
- `LocationView` — работает и с системными, и с пользовательскими локациями

### Backend (уже было реализовано)
- `DataInitializer` — создаёт район «Центральный» + 8 системных локаций с комнатами при старте
- `DistrictController` — REST API для районов
- `LocationController.getRooms()` — работает для любой локации по ID
